# Reproducing PLTE

There are three different reproduction tiers. Keep them separate: repository integrity does not remeasure distortion, and block replay does not establish a whole-checkpoint result.

## Tier 1: verify published bytes without Qwen weights

From the repository root:

```bash
python tools/verify_repository.py
```

This uses only the Python standard library. It verifies implementation hashes, all 49 report/container pairs, literal audit flags, the six serialized masks, eight clean-decoder reports, the router artifact, and ledger invariants.

## Exact experimental environment

Evidence was generated with:

- Python 3.12.3;
- NumPy 2.5.2;
- SciPy 1.18.1;
- CuPy 14.2.0 (`cupy-cuda12x`);
- NVIDIA RTX A6000;
- NVIDIA driver 580.159.03.

Create an isolated environment appropriate for your CUDA installation:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The evidence encoder is GPU/CuPy code. The clean decoder is NumPy/SciPy code by design, providing an implementation boundary from the encoder.

## Pin the upstream polar reference

The reliability-order and numerical reference checkout is not vendored because its upstream repository has no detected license file. Clone it separately and pin the audited commit:

```bash
mkdir -p external
git clone https://github.com/graceBaoXP/PolarLatticeQuantization.git external/PolarLatticeQuantization
git -C external/PolarLatticeQuantization checkout 458187b9b03db1768a4b72d617e591f7862f6fca
```

Always pass this path explicitly. The exact evidenced scripts retain their original machine-specific `/root/PolarLatticeQuantization` default to preserve their SHA-256 provenance.

## Tier 2: materialize source blocks and replay metrics

The repository excludes raw Qwen BF16 bytes. The helper below downloads the 47 unique evidence blocks from the immutable revision and arranges them under the exact paths expected by the pinned ledger:

```bash
python tools/materialize_sources.py
```

The helper validates every downloaded block against the SHA-256 in the evidence manifest. Raw weight files are covered by `.gitignore`.

To include all 48 router matrices for router-codec regeneration:

```bash
python tools/materialize_sources.py --include-routers
```

The fetcher performs HTTP range requests against:

```text
Qwen/Qwen3-30B-A3B
revision ad44e777bcd18fa416d9da3bd8f70d33ebb85d39
```

### Clean-decode a normative heavy-tail block

After materializing sources:

```bash
cd plte
python agent_polar_codec_audit_independent_decoder.py \
  --container agent_root_polar_escape_normative_embed_b0.polar.bin \
  --metadata agent_root_polar_escape_normative_embed_b0.json \
  --raw-mask agent_root_polar_escape_frozen_profiles.bin \
  --source-bf16 qwen_weight_cache/range_blocks/model.embed_tokens.weight.block0.bf16.bin \
  --output reproduced_embed_b0_standalone.json
```

Expected relative MSE: `0.032266665312005456`. Expected container SHA-256: `4fa0fc6690142bb89b1af10a020c47114879995cb5f7032cddd50ab76c2f1bc6`.

Omit `--source-bf16` to reconstruct decoded weights without auditing MSE.

## Tier 3: regenerate encoder outputs

### Re-export the frozen masks

Do this before rebuilding the ledger:

```bash
cd plte
python agent_root_export_polar_profile.py \
  --polar-repo ../external/PolarLatticeQuantization \
  --output reproduced_frozen_profiles.bin
```

The resulting SHA-256 must be:

```text
11efea4247aadfb8d30369483a9753921f46f93f8cc2c0e94325538b159b29a6
```

### Encode one frozen Qwen block

```bash
python agent_root_polar_lattice_gate.py \
  --polar-repo ../external/PolarLatticeQuantization \
  --input-bf16 qwen_weight_cache/range_blocks/model.embed_tokens.weight.block0.bf16.bin \
  --emit-container-hex \
  --output reproduced_embed_b0.json
```

The source path recorded in the JSON is part of that JSON's hash. Encoding identical bytes from a different path can produce the same `.polar.bin` while producing different metadata bytes.

### Rebuild the pinned ledger

With all evidence sources materialized, run from `plte/`:

```bash
python agent_root_polar_escape_full_model_ledger.py \
  --output reproduced_full_model_ledger.json
```

The default run consumes the pinned evidence manifest. Do not pass `--refresh-evidence-manifest` unless intentionally constructing a new evidence set; refreshing changes the provenance boundary.

Expected central values:

```text
conditional global rate: 2.4801720791097526 bpw
projected relative MSE:  0.03273955118126599
projected Gaussian gap:  0.08285101917462104 dB
```

As a publication audit, the helper refetched all 47 source blocks and the ledger regenerated byte-identically with SHA-256 `044613b336db84d393509d736ec9d5782a039c3e425f960bce8dbcbfa35ebbff`.

### Regenerate the all-router artifact

After `materialize_sources.py --include-routers`:

```bash
python agent_router_adaptive_q234.py \
  --input-dir qwen_weight_cache/range_blocks \
  --threshold 0.045 \
  --iterations 30 \
  --output-json reproduced_router_all48.json \
  --output-bin reproduced_router_all48.bin
```

Expected literal router container SHA-256:

```text
31de0cc8f7a7a97b12c72440f680a22bdd0494f8fe474254257e7f9ea1c9dab6
```

## Portability warning

The encoded evidence pins the exact encoder implementation. Its SHA-256 is `4d76ba53c88710778085917108b7940517ed14565815fc8437ea4919d7df4bf8`. Do not edit that file and still claim byte-level provenance for the published streams.

Probability regeneration currently uses floating-point numerical behavior. A production format needs either a completely pinned runtime/math stack or a normative fixed-point/LUT probability implementation.

## This is not full-checkpoint reproduction

The commands above reproduce the published selected-block evidence. They do not encode the remaining 116,375 non-router blocks, implement overflow handling, build a concatenated checkpoint, or measure model accuracy.
